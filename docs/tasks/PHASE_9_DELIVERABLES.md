## Purpose

When a project or a task has deliverables, Cosmin reaches them from the app: a file is kept on the Mac and can be seen and opened; a folder of code opens in the IDE or the Finder; the important run commands (`package.json` scripts and the like) are listed and run from the panel with live output; an application opens; an image is shown. Agents declare deliverables, the server detects the project folder and its run scripts, and the user adds or removes them by hand. The phone lists, views, downloads and may stop a run; only the Mac opens, launches and starts runs. What has to be copied goes into a `deliverables/` folder inside the project's own folder (e.g. `~/GalacticProjects/my-app/deliverables/`), excluded from git locally, that belongs to the user.

## Design notes for implementation

- **A deliverable is a pointer.** The row says where the thing is; the bytes stay in the project's folder (its `deliverables/` folder included) or the task's worktree. File facts (exists, size, text or binary) are computed on read and never stored as truth.
- **One vocabulary.** `packages/protocol/src/deliverables.ts` holds the types; the world fold in `packages/protocol/src/world.ts` folds `deliverable.*` and `run.*`, so the client, the import and the conformance test agree. New snapshot fields and events are optional for the previous build's parser (TECHNOLOGY §6.3 rule 5); the run output stream is a new socket message only sent to a page that subscribed.
- **Paths are checked on the real path, every time.** `deliverables/paths.ts` is pure over an `fs` facade; reads go through a descriptor opened with `O_NOFOLLOW` and compared with the checked path's `(dev, ino)`. Never a path from a request: routes take a deliverable id.
- **The merge hook runs inside the repository lock.** `beforeWorktreeRemoved` is called by `mergeTask` / `removeWorktree` after the merge and before `git worktree remove --force`; it never fails the merge.
- **Runs reuse the supervisor, not the agent machinery.** `ProcessSpec.owner = {kind: 'run', id}`: PID row `run:<id>`, launch intent, `GALACTIC_RUN_ID` marker, no agent marker, no caps, no status record. Stopping reuses the identity-checked signalling of `StewardProcesses`.
- **Remote rules are a table** (TECHNOLOGY §9.9). Opening, launching, starting and restarting runs use `requireLocal(req, {always: true})` (403 `remote_control`, not lifted by `autoApproveRemote`); stopping a run is open to the phone; edits by hand and the `deliverables.*` settings use the decision-51 rule (403 `remote_control` / `remote_settings` unless `autoApproveRemote`).
- **The deliverables folder is the user's.** No code path deletes a file or folder under a project's `deliverables/` folder; a test walks every removal, archive, cancel and retention path and checks the folder is untouched.
- **Tests:** the fake adapter and scripted brains (`brains/testing/`) for declarations; temporary folders and a temporary git repository for paths, copies and merges; a fake `open` (injected `execFile`) for the opener; a real `/bin/sh` child for runs (a script that prints a URL and listens on a port), with the supervisor's test probe for the restart pass. Real-Claude and real-IDE checks are local only and tagged.
- **Decided before implementation** (Cosmin, 2026-10-07): runs are gated by his confirmation only — the permission table does not apply (decision 129); the phone may stop a run, never start one (decision 131); copies go into a `deliverables/` folder inside the project's own folder, one subfolder per task, excluded from git through the repository's local `.git/info/exclude`, under the existing projects-root setting (default `~/GalacticProjects`), never deleted from by the app (decision 122); no size limits on files other than a free-space guard, with preview limits only in the page (decisions 122, 125); run concurrency, run-output retention and agent declaration limits are settings (decisions 120, 130); ACP Stewards declare through their supervisor's report for now (decision 120); `react-markdown`, `highlight.js` (lazy) and `smol-toml` are accepted; `phase-9` is the phase branch. Still open, with conservative defaults: SPEC §8 (2026-10-07 rows).

## Exit criteria (from the plan)

On the Mac, a Steward on real Claude finishes a task that builds a small web app and a screenshot: the screenshot shows in the Steward view and, after the Waykeeper's merge, still shows from the project's Deliverables (re-pointed into the project's folder, or copied into the project's own `deliverables/` folder — `~/GalacticProjects/<project>/deliverables/<task>/`, excluded from git locally — which Reveal in Finder opens); the project folder opens in WebStorm and in the Finder; `pnpm dev` from `package.json` runs from the panel after a confirmation, its output streams, its port opens in the browser, and Stop ends it and everything it started; closing the project stops a run left running; after a server restart the run shows stopped and nothing is left of it. From the phone the same deliverables are listed, the screenshot and a text file are viewed and a file downloaded, and the running command is stopped (after a confirmation), while every open, launch and start of a run is refused. An agent's attempt to declare a path outside the project (a private key, a symlink out of the worktree) is refused.
